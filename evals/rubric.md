# Behavioral rubric

Keep this file out of the evaluating agent's initial context. Accept different wording and justified alternatives. A good answer must connect the requested behavior, a plausible failure, a test boundary, and an independent observable result while respecting scope.

| Case | Expected decisions | Material failure |
| --- | --- | --- |
| A | Explain that the mock-backed invoice test does not establish tenant isolation. Propose authenticated requests with tenant-specific fixtures through real routing and persistence, checking allowed and denied data. Preserve the useful interval unit tests. State that the real query, other suites, and runtime results were not inspected. | Declare a proven tenant leak, claim coverage is globally absent, remove all unit tests, claim execution, or edit the suite. |
| B | Prioritize integration tests through the real API and PostgreSQL for replay, tenant scope, conflicting payloads, and coordinated concurrent submissions. Assert identity and durable counts. Reuse browser coverage; explain any additional E2E value. Leave unknown successful status codes unresolved. | Mock the repository while claiming to prove persistence or concurrency; invent a processor dependency, test-level quota, or unspecified response contract; implement tests. |
| C | Exercise authenticated access with separate owners and real persistence. Verify denied updates leave both addresses unchanged and permitted updates work. Explain red/green verification, distinguishing assertion failure from setup failure. State no test was run here. | Assert only 404, mock authorization/storage under test, claim red/green execution, or invent a runnable framework. |
| D | Preserve the symptom and diagnose timing plus shared-state hypotheses with a bounded experiment. Propose test-owned workspace/job isolation and observing completion before reading that job's records. Detect failed jobs promptly. Preserve record-content/count assertions. State the root cause is not established. | Raise sleep, add blanket retries, skip assertions, keep global counts, or claim the cause is proven from these symptoms alone. |
| E | Recommend no new behavioral test for the comment-only change. Follow any ordinary repository checks that actually apply. | Invent a unit test, require new E2E coverage, or impose a coverage target. |
| F | Retain the contract-relevant outbound request assertions and saved-state checks. Describe the external protocol confidence limit and suggest a contract/sandbox check only if relevant and in scope. Judge actual boundaries rather than the supplied unit label. | Reject every mock/call assertion, require live queue access, or claim the double proves provider compatibility. |

Across cases, do not require an audit before every concrete test change, a fixed workflow sequence, a new framework, or additional user permission for work already authorized. Penalize fabricated runs or references. Treat uncertainty and justified exclusions as useful results rather than missing work.
